# 回复验证码与旧评分清理

全站普通回复和发起大乱斗共用 `user_id` 的小时计数，每轮随机选择 80～120 次门槛，达到后下一次提交要求验证码。窗口从本轮首个成功回复开始计算 3600 秒，后续回复不续期；验证成功或窗口到期后重新开始一轮。换 IP、换主题不会重置账号计数。业务失败释放预占额度，事务已经提交的回复仍计数。

每 IP 每分钟 10 次回复（包含大乱斗）、发新主题间隔、抢回帖红包每 IP 每 5 分钟 6 次，以及原有管理员和本人红包豁免继续有效。回复验证码成功不会清除 IP 分钟限流或红包计数。

`GET /api/captcha` 需要登录，不增加请求参数。验证码绑定账号，60 秒有效，提交一次即消费，错误后须换图。`POST /api/user/water_unlock` 沿用 `type=new_post|hongbao_store` 选择解除的限制；同一验证码只能用于其中一项。旧回复轮次的验证码不会清除新轮次。两个接口分别按账号限制为每分钟 10 次。

评分、刷帖/抢红包警报、JS 签名异常及验证码错误不再写入 `user_actives_*`；已入队的这六类旧任务也直接跳过。其他用户活动与历史数据保留。后台“种田巡逻”和 `/api/admin/antibot_scores` 已移除。旧客户端仍可携带 `new_post_key`、`timestamp`，后端不再使用这些字段。

## 发布和清理

无数据库迁移或新增环境配置。前后端一同发布，重新加载旧页面。现有生产发布工作流会重启队列 worker；手动部署也需重启长驻 worker，使旧任务使用新版处理逻辑。

账号计数使用新的 Redis 前缀 `post_captcha_user:`，验证码使用 `water_captcha_user:`，上线时小时额度从零开始。旧验证码最多 60 秒内失效，遇到过期提示换图即可。

在所有实例已更新、不再产生旧评分记录后，先预览再清理：

```bash
php artisan antispam:cleanup-legacy --dry-run
php artisan antispam:cleanup-legacy
```

本地 Docker 环境在命令前加 `docker compose exec php`。命令仅在当前应用 Redis 前缀内分批扫描并异步删除 `post_timeline:*`、`new_post_record_IP2_*`、`new_post_record_IP_*`。不会删除分钟限流、红包计数、新账号计数或任何数据库记录；无需也不可使用 `FLUSHDB`。

上线后用现有监控对比回复响应耗时、Redis 调用量和队列负载。固定窗口允许到期后恢复，低于门槛的慢速脚本仍可能继续；随机验证码不作为机器人身份判定或自动处罚依据。
